# 厦门在招岗位爬取与匹配筛选系统

> 把厦门大学就业信息网上「你能投、且值得投」的岗位筛出来，导成一份可以直接照着投的 Excel 清单。

**数据来源**：厦门大学就业信息网（https://jy.xmu.edu.cn）· 公开页面，无需登录

---

## 一、项目定位与核心功能

### 它解决什么问题

学校就业网上的在招岗位有几百条，但只能按单个条件筛选；你真正想知道的是「哪些岗位既在我的专业口径内、又是我该投的方向」——这个判断目前只能一条条翻。

本项目把这件事自动化：**按条件取数 → 逐条打匹配分 → 存进本地库 → 任意条件反复筛 → 导出 Excel**。

### 核心功能

| 功能 | 说明 |
|---|---|
| 多维条件检索 | 直接调用站点自带的筛选能力，按 城市 / 学历 / 工作性质 / 发布时间 / 最低薪资 / 需求专业 精确取数，而不是先把全国岗位抓回来再本地过滤 |
| 匹配度打分 | 每条岗位给出匹配分与 S/A/B/C 等级，并写明「为什么给这个分」——命中了哪些关键词 |
| 一次取数、反复筛选 | 岗位全量存进本地数据库，之后调整筛选条件是毫秒级、且不需要联网 |
| 条件可存可复用 | 检索条件和筛选条件都能存成方案文件，下次一条命令直接套用 |
| 成品 Excel | 14 列完整字段（含投递方式、截止时间、原文链接），按匹配等级着色、冻结首行 |

### 输出长什么样

导出的清单按「目标城市优先 → 匹配分从高到低」排序。当前库中的高匹配岗位示例：

| 等级 | 匹配分 | 公司 | 岗位 |
|---|---|---|---|
| S | 27 | 福建活石网络科技 | 数据分析/软件开发管培生 |
| A | 24 | 厦门微著智能装备 | CT重建算法工程师 |
| A | 20 | 厦门海景微电子 | AI开发工程师 |
| A | 19 | 厦门金美信消费金融 | 开发工程师 |

### 当前实测规模

- 本地库 **284 条**厦门岗位（本科 · 全职），覆盖 **108 家公司**
- 区域分布：思明 93 / 湖里 55 / 海沧 29 / 同安 21 / 翔安 17 / 集美 10
- 自动化测试 **116 个用例**，全部通过

## 二、主要使用场景

**1. 秋招找厦门的对口岗位（主线用法）**
默认口径就是为「数学类本科 · 2027 届 · 目标厦门」准备的：厦门 + 本科 + 全职 + 数学与统计类专业。跑一次就能拿到一批候选，重点看 S / A 级。

**2. 判断「机会盘子有多大」**
同一个市场按不同口径取数看差异：只按本专业精确匹配约 30 条，放宽到「不限专业」约 300 条。这个对比能帮你决定是该收窄方向还是扩大投递面。

**3. 盯新增岗位**
用发布时间条件只取近 3 天 / 近 1 周的岗位，每周跑一次，不用反复翻看老岗位。

**4. 换城市、换专业复用**
检索条件是参数化的，换成福州、泉州或换一个专业口径，同一条命令就能拿到另一批结果，适合横向对比异地机会。

**5. 快速排除噪音**
用排除词一次性滤掉销售、客服、市场推广这类明显不对口的岗位。

## 三、安装与快速上手

### 环境要求

- Windows（批处理入口为 Windows 原生脚本）
- Python 3.8 及以上
- 依赖库见 `requirements.txt`：requests / beautifulsoup4 / lxml / pandas / openpyxl

### 方式一：双击运行（最省事）

在项目目录下**双击 `一键运行.bat`**。它会自动找到可用的 Python 解释器、检查依赖（缺了就按 `requirements.txt` 自动安装），然后执行完整流程。

想带参数时，在项目目录开一个命令行窗口，用通用入口 `run.bat`：

```bat
run.bat --stats
run.bat --skip-crawl --city 厦门 --min-score 16 --level S,A
run.bat test          :: 跑一遍自动化测试，确认环境没问题
```

> `run.bat` 会自动按 `.\.venv` → `.\venv` → 环境变量 `%PYTHON%` → `PATH` 中的 `python` 依次寻找解释器。
> 如果 Python 装在别处，把 `local.bat.example` 复制成 `local.bat`，在里面填一行解释器路径即可（该文件不会进入版本库）。

### 方式二：命令行运行

```bash
# 建虚拟环境并安装依赖（只需一次）
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# 运行
python main.py
```

### 怎么算「跑通了」

执行结束后，你会看到流水线逐步打印，并以类似下面的结果收尾：

```
[1/5] 检索岗位（使用站点自带的多维筛选） ...
      取到 284 条岗位（列表请求 16 次，详情请求 284 次）
      其中取到「需求专业」的 270 条

[2/5] 专业匹配度打分 ...
      等级分布：S(极高匹配)=1 | A(高度匹配)=13 | B(一定匹配)=38 | C(相关性较弱)=232

[3/5] 入库（按 公司+岗位 去重） ...
      新增 284 条，重复跳过 0 条

[4/5] 按条件筛选 ...
      命中 14 条 / 库中共 284 条

[5/5] 导出 Excel ...
      已导出：...\output\岗位清单_厦门_SA_min16_20260920_223512.xlsx
```

导出文件在 `output/` 目录下。**第一次跑想先确认环境正常、又不想等**，可以小规模试跑：

```bash
python main.py --max-pages 2 --detail-limit 10
```

## 四、典型用法示例

### 日常三招

```bash
# 1. 看库里现在有什么（不联网、不导出）
python main.py --stats

# 2. 只挑高匹配的，秒级出清单
python main.py --skip-crawl --min-score 16 --level S,A

# 3. 只看近一周新发的岗位
python main.py --search-time 近1周
```

### 取数口径（决定向站点要哪一批岗位）

| 命令 | 效果 |
|---|---|
| `python main.py` | 默认口径：厦门 + 本科 + 全职 + 数学/统计类专业，约 30 条候选 |
| `python main.py --search-major 不限` | 放开专业限制，取厦门全部本科全职岗位，约 300 条 |
| `python main.py --search-city 福州` | 换成福州（支持厦门/福州/泉州/漳州等，填中文名） |
| `python main.py --search-time 近3天` | 只取近 3 天发布的 |
| `python main.py --search-salary-min 8000` | 只取月薪 8000 起的 |
| `python main.py --no-detail` | 不抓详情页，速度快很多，但缺「需求专业」，匹配分仅供参考 |
| `python main.py --max-pages 2 --detail-limit 10` | 快速试跑：只取 2 页列表、前 10 条详情 |

### 筛选条件（决定导出清单里留哪些）

| 参数 | 效果 |
|---|---|
| `--city 厦门` / `--city 厦门,福州` | 限定城市，多个用逗号分隔 |
| `--min-score 16` | 最低匹配分（S≥25 / A≥16 / B≥8） |
| `--level S,A` | 只要指定等级 |
| `--keyword 数据` | 关键词，匹配公司名或岗位名 |
| `--major 数学` | 专业要求里必须含「数学」 |
| `--exclude 销售,客服` | 排除关键词 |
| `--top 20` | 最多输出 20 条 |
| `--out 我的清单.xlsx` | 指定导出文件名（默认按条件自动命名） |

### 数据维护

```bash
# 清空数据库后重新取数（换了口径、或想从头来时用）
python main.py --reset-db --city 厦门

# 改了打分规则后重算全部分数（不联网，秒级）
python main.py --rescore
```

### 把一套条件存下来反复用

```bash
# 检索方案
python main.py --search-city 厦门 --search-major 不限 --save-search xiamen-all.json
python main.py --search-file xiamen-all.json

# 筛选方案
python main.py --city 厦门 --min-score 16 --level S,A --save-filter focus.json
python main.py --skip-crawl --filter-file focus.json
```

命令行参数的优先级高于方案文件，临时想改某个条件，直接加在命令后面即可覆盖。

`python main.py -h` 可以查看全部参数。

## 五、配置说明

所有可调项集中在 `config.py`，改配置不需要动其他代码。

### 检索范围与排序

| 配置项 | 作用 | 默认值 |
|---|---|---|
| `TARGET_CITY` | 目标城市，决定排序时谁排最前 | `厦门` |
| `DEFAULT_MAJOR_KEYS` | 默认专业口径（可投的专业范围） | 信息与计算科学、数学类、统计学 |
| `MAJOR_CODES` | 专业名称 → 站点代码对照表 | 已含数学类、统计、计算机、软件工程等 |
| `CITY_CODES` | 城市名称 → 行政区划代码对照表 | 福建省各市 + 主要一二线城市 |
| `PROVINCE_CITIES` | 同省城市清单，用于「同省岗位优先排序」 | 福建、江苏 |

> 检索条件里的城市、学历、专业都填**中文名**，程序会自动翻译成站点需要的代码。

### 打分规则

分数 = **岗位方向分（看岗位名称）** + **专业准入分（看专业要求）** − 反向词扣分。

| 配置项 | 作用 |
|---|---|
| `DIRECTION_WEIGHTS` | 岗位方向词表：数据 / 算法 / 开发等方向各值多少分 |
| `KEYWORD_WEIGHTS` | 专业关键词表：专业要求里出现「信息与计算科学」「数学类」等各加多少分 |
| `NEGATIVE_KEYWORDS` | 反向词表：命中销售、客服等直接扣分 |
| `MATCH_LEVELS` | 等级阈值：S≥25 / A≥16 / B≥8 / C≥0 |

想调整「什么算对口」，改这几张表就够了；改完执行 `python main.py --rescore`，已有数据会用新规则重算。

### 输出与采集节奏

| 配置项 | 作用 | 默认值 |
|---|---|---|
| `OUTPUT_COLUMNS` | Excel 的列与顺序 | 14 列，含投递方式与原文链接 |
| `EXCEL_SHEET_NAME` | 工作表名称 | `岗位匹配结果` |
| `REQUEST_DELAY_SECONDS` | 每次请求的间隔秒数 | `1.5`（请勿调小） |
| `SEARCH_MAX_PAGES` | 翻页安全上限 | `60` |

### 目录与文件

| 路径 | 说明 |
|---|---|
| `config.py` | 全部可调配置 |
| `data/jobs.db` | 本地岗位库（SQLite，自动创建） |
| `output/` | 导出的 Excel（自动创建） |
| `local.bat` | 本机解释器路径（可选，不入版本库；模板见 `local.bat.example`） |

## 六、常见问题

**Q：运行时报 `ModuleNotFoundError: No module named 'pandas'`**
说明当前用的是没装依赖的 Python。改用 `run.bat` 运行——它会自动挑选可用的解释器，缺依赖会自动安装。如果你自己建了虚拟环境，先激活再运行。

**Q：提示「未取到任何岗位」**
先检查检索条件拼写：城市、学历、工作性质都要用中文名（如「厦门」「本科」「全职」）。仍不行的话，单独跑一次采集自测，可以直接看到请求与解析过程：

```bash
python -m spiders.xmu_career
```

**Q：筛选结果是 0 条**
先执行 `python main.py --stats`，看库里实际有哪些数据，再放宽条件：调低 `--min-score`、去掉 `--city`，或换用更宽的 `--level`。

**Q：想清空重来，或库里混进了不需要的岗位**
用 `--reset-db` 在下次取数前清空数据库：`python main.py --reset-db --city 厦门`。

**Q：改了 `config.py` 的权重表，但分数没变**
已有记录的分数不会自动更新。执行 `python main.py --rescore`，按新规则重算库里全部岗位（不联网）。

**Q：为什么很多岗位是 B 级或 C 级？**
等级是分层池子，不是合格线：S≥25 重点看，A≥16 值得投，B≥8 可以扫一眼，C 基本不对口。库里绝大多数岗位来自整个厦门招聘市场（教师、销售、行政、制造等），它们落在 C 级是正常的——**筛不出对口岗位才是问题，C 级多不是**。

**Q：有些岗位没有薪资或专业要求**
站点本身没有提供该字段。程序的原则是**保留而不是剔除**——信息缺失不等于不满足条件，宁可多给你看一条。若某条岗位的专业字段确实取不到，会标注「专业字段缺失」，不会被当成「不匹配」。

**Q：取一次数据要多久？会不会给站点造成压力？**
默认口径（约 30 条）约 1 分钟；放开专业取全量（约 300 条）约 8-10 分钟，主要时间花在逐条补「需求专业」上。程序对每次请求都做了 ≥1.5 秒的节流，并且只抓公开页面、不登录、不绕过任何访问控制。

**Q：能用在别的城市或别的学校吗？**
城市可以直接换——从 `CITY_CODES` 里挑一个填到 `--search-city` 即可。换到其他学校的就业网站，则需要另写一个对应的采集模块。
